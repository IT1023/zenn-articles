# English
This article presents a clean and flexible implementation of a dual token authentication system using short-lived access tokens and long-lived refresh tokens.

This implementation consists of three main parts:

• A backend issuing and validating access + refresh tokens
• A frontend using Redux to manage authentication state
• An interceptor system that automatically handles token expiration and retries requests

The access token is short-lived (~15 minutes) and sent via headers, while the refresh token is long-lived (~7 days) and stored in an HTTP-only cookie.

The backend returns standardized error codes for every request:

• invalid_request
• invalid_token
• expired_token
• malformed_token

This pattern is particularly useful when:

• You want secure session management without storing long-lived tokens in JS
• You want a scalable and predictable authentication flow

Step 1: Token Strategy Overview

We use two tokens:

• Access Token

Short-lived (~15 minutes)
Stored in memory (Redux)
Sent via Authorization header

• Refresh Token

Long-lived (~7 days)
Stored in HTTP-only cookie
Used only to generate a new access tokens

This separation minimizes risk exposure while maintaining usability.

Step 2: Backend – Token Generation

We generate both tokens during login.

```ts
// utils/helpers.ts
import jwt from "jsonwebtoken";

const ACCESS_SECRET = "access_secret";
const REFRESH_SECRET = "refresh_secret";

export function generateTokens(userId: string) {
  const accessToken = jwt.sign({ userId }, ACCESS_SECRET, {
    expiresIn: "15m",
  });

  const refreshToken = jwt.sign({ userId }, REFRESH_SECRET, {
    expiresIn: "7d",
  });

  return { accessToken, refreshToken };
}
```

Step 3: Storing Refresh Tokens (Simplified)

For simplicity, refresh tokens are stored in a data.json file.

```ts
// data.json
{
  "refreshTokens": []
}
```

```ts
// utils/helpers.ts
import fs from "fs";

export function saveRefreshToken(token: string) {
  const data = JSON.parse(fs.readFileSync("data.json", "utf-8"));
  data.refreshTokens.push(token);
  fs.writeFileSync("data.json", JSON.stringify(data));
}

export function isValidRefreshToken(token: string) {
  const data = JSON.parse(fs.readFileSync("data.json", "utf-8"));
  return data.refreshTokens.includes(token);
}
```

Step 4: Login Route

On login:

• Generate tokens
• Store refresh token
• Send access token in response
• Set refresh token as HTTP-only cookie

```ts
// login.route.ts
import { serialize } from "cookie";

app.post("/login", (req, res) => {
  // for simplicity, we are pretending to sent userId, in request
  // irl production: validate email, password, and fetch userId
  // from db
  const { userId } = req.body;

  const { accessToken, refreshToken } = generateTokens(userId);

  saveRefreshToken(refreshToken);

  const cookie = serialize("refreshToken", refreshToken, {
    httpOnly: true,
    path: "/",
    maxAge: 7 * 24 * 60 * 60, // seconds
    sameSite: "strict",
    secure: false, // true in production (HTTPS)
  });

  res.setHeader("Set-Cookie", cookie);

  res.json({ accessToken });
});
```

Step 5: Middleware – Access Token Validation

Every protected route must validates the access token and returns structured errors.

```ts
// auth.middleware.ts
export function authMiddleware(req, res, next) {
  const authHeader = req.headers.authorization;

  if (!authHeader) {
    return res.status(400).json({ code: "invalid_request" });
  }

  const token = authHeader.split(" ")[1]; // standard request is to send
  // the token with a Bearer request

  if (!token) {
    return res.status(400).json({ code: "malformed_token" });
  }

  try {
    const decoded = jwt.verify(token, ACCESS_SECRET);
    req.user = decoded;
    next();
  } catch (err: any) {
    if (err.name === "TokenExpiredError") {
      // expired token, needs to be intercepted by frontend for a
      // re-request
      return res.status(401).json({ code: "expired_token" });
    }

    return res.status(401).json({ code: "invalid_token" });
  }
}
```

Step 6: Refresh Token Endpoint

When the access token expires, the frontend calls /refresh.

```ts
// refresh.route.ts
import { parse } from "cookie"
app.post("/refresh", (req, res) => {
  const cookies = parse(req.headers.cookie ?? "");
  const token = cookies.refreshToken;

  if (!token) {
    return res.status(401).json({ code: "invalid_request" });
  }

  if (!isValidRefreshToken(token)) {
    return res.status(401).json({ code: "invalid_token" });
  }

  try {
    const decoded = jwt.verify(token, REFRESH_SECRET);

    const newAccessToken = jwt.sign(
      { userId: decoded.userId },
      ACCESS_SECRET,
      { expiresIn: "15m" }
    );

    res.json({ accessToken: newAccessToken });
  } catch {
    return res.status(401).json({ code: "expired_token" });
  }
});
```

Step 7: Frontend – Redux Auth Slice

Redux stores the access token in memory.

```ts
// auth.slice.ts
import { createSlice } from "@reduxjs/toolkit";

const authSlice = createSlice({
  name: "auth",
  initialState: {
    accessToken: null as string | null,
  },
  reducers: {
    setToken: (state, action) => {
      state.accessToken = action.payload;
    },
    clearToken: (state) => {
      state.accessToken = null;
    },
  },
});

export const { setToken, clearToken } = authSlice.actions;
export default authSlice.reducer;
```

Step 8: Axios Interceptor – Handling Expired Tokens

We intercept responses and retry requests automatically when the token expires.

```ts
// modify axios to inject token on every request
import axios from "axios";
import store from "./store";
import { setToken, clearToken } from "./authSlice";

const api = axios.create({
  baseURL: "/api",
  withCredentials: true,
});

api.interceptors.request.use((config) => {
  const token = store.getState().auth.accessToken;

  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }

  return config;
});
```

Step 9: Response Interceptor (Auto Refresh)
```ts
// modify axios to intercept expired_token requests and call for a refresh
api.interceptors.response.use(
  (res) => res,
  async (error) => {
    const originalRequest = error.config;

    if (error.response?.data?.code === "expired_token") {
      try {
        const res = await axios.post("/api/refresh", {}, { withCredentials: true });

        store.dispatch(setToken(res.data.accessToken));

        originalRequest.headers.Authorization = `Bearer ${res.data.accessToken}`;

        return axios(originalRequest);
      } catch {
        store.dispatch(clearToken());
      }
    }

    return Promise.reject(error);
  }
);
```

Step 10: Usage Example
```ts
const fetchUser = async () => {
  const res = await api.get("/me");
  return res.data;
};
```

If the access token expires:

• Backend returns expired_token
• Interceptor calls /refresh
• New access token is stored
• Original request is retried automatically

Final Complete Flow:
• User logs in
• Backend issues:
    • Access token (response)
    • Refresh token (HTTP-only cookie)
• Frontend stores access token in Redux
• Requests include access token in headers
• If expired:
    • Backend returns expired_token
    • Frontend calls /refresh
    • Retries original request

What This Implementation Provides:
• Secure token separation (access vs refresh)
• Automatic session recovery
• Redux-based state management
• Standardized backend error handling
• Clean and scalable architecture

All while keeping authentication logic predictable and decoupled between frontend and backend.

• invalid_request
• invalid_token
• expired_token

• 長寿命トークンをJavaScriptに保存せず、安全にセッション管理を行いたい場合

Step 1: トークン戦略の概要

2種類のトークンを使用します：

• アクセストークン

短命（約15分）
メモリ（Redux）に保存
Authorizationヘッダーで送信

• リフレッシュトークン

長寿命（約7日）
HTTP-onlyクッキーに保存
新しいアクセストークンを生成するためのみに使用

この分離により、セキュリティリスクを最小化しつつ、ユーザビリティを維持できます。
