# English Version.

This article presents a clean, generic, and safe implementation of an in-memory cache with automatic expiration (TTL) using JavaScript’s Proxy object.
The custom_cache function returns an object that behaves like a normal JavaScript object but automatically removes entries after a specified time, while reseting the expiration timer on every cache hit, and works seamlessly with any data type thanks to TypeScript generics.

This pattern is particularly useful when:
You need a light and small zero-dependency cache (e.g., API response caching, memoization)
You want to prevent memory leaks from stale data (Pagination is still prefered, this may replace it in small apps).
You want junior developers or interns to use caching safely without remembering to manually invalidate entries

** Step 1: Function Definition and Timeouts State
We start by defining the function that receives the TTL (in milliseconds) and prepares two objects:

• cache: stores the actual values
• timeouts: tracks active setTimeout references so we can remove and reset expiration on access

```js
function custom_cache<T>(ttl: number) {
  const timeouts: Record<string, ReturnType<typeof setTimeout>> = {};
  type TCache = Record<string, T>;
  const cache: TCache = {} as TCache;
  
  // Proxy will be returned
}
```

** Step 2: The get Trap – Cache Hit and Timer Reset
When a property is read:

• If it doesn’t exist → return undefined
• If it exists → cancel the previous timeout, start a fresh TTL timer, and return the value

```js
get(target: TCache, prop: string) {
  if (!(prop in target)) return undefined;
  
  // Cancel previous expiration
  clearTimeout(timeouts[prop]);
  
  // Start new timeout
  timeouts[prop] = setTimeout(() => {
    delete target[prop];
    delete timeouts[prop];
  }, ttl);

  return target[prop];
}
```

** Step 3: The set Trap – Store Value and Schedule Timeout When a value is assigned:

• Cancel any existing timeout for that key
• Store the value
• Schedule automatic deletion after ttl milliseconds

```js
set(target: TCache, key: string, value: T) {
  // Cancel previous timer if exists
  if (timeouts[key]) clearTimeout(timeouts[key]);

  // Schedule deletion
  timeouts[key] = setTimeout(() => {
    delete target[key];
    delete timeouts[key];
  }, ttl);

  // Actually store the value
  target[key] = value;
  return true;
}
```

** Step 4: Returning the Proxy

```js
return new Proxy(cache, {
  get(target, prop: string) {
    // ... (same as Step 2)
  },
  set(target, key: string, value: T) {
    // ... (same as Step 3)
  }
});
```

** Final Complete Implementation

```js
function custom_cache<T>(ttl: number) {
  const timeouts: Record<string, ReturnType<typeof setTimeout>> = {};

  type TCache = Record<string, T>;
  const cache = {} as TCache;

  return new Proxy(cache, {
    get(target: TCache, prop: string) {
      if (!(prop in target)) return undefined;

      clearTimeout(timeouts[prop]);
      timeouts[prop] = setTimeout(() => {
        delete target[prop];
        delete timeouts[prop];
      }, ttl);

      return target[prop];
    },

    set(target: TCache, key: string, value: T) {
      if (timeouts[key]) clearTimeout(timeouts[key]);

      timeouts[key] = setTimeout(() => {
        delete target[key];
        delete timeouts[key];
      }, ttl);

      target[key] = value;
      return true;
    },
  });
}
```

Usage Examples

```js
// Simple string cache (5 seconds TTL)
const cache = custom_cache<string>(5000);

cache.name = "Taha";
console.log(cache.name);        // Cache Hit ... → "Taha"

setTimeout(() => {
  console.log(cache.name);      // undefined
}, 6000);

// Object cache
interface User {
  id: number;
  name: string;
}

const userCache = custom_cache<User>(10_000);
userCache["user:42"] = { id: 42, name: "Taha" };

console.log(userCache["user:42"]?.name); // Cache Hit ... → "Taha"

// Timer resets on every access
setTimeout(() => console.log(userCache["user:42"]?.name), 15_000); // Still "Taha" if accessed in between (timeout refresh)
```

This tiny function provides a type-safe, automatically expiring cache perfect for client-side state, request deduplication.
